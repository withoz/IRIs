## 확정 사항과 귀결 (2026-09-07)

최초 미결정 5개가 전부 확정됐습니다. **각 결정이 무엇을 닫았는지**가 아래의 요점입니다.

### ① 1순위 호스트 앱 = SketchUp

근거: [과제 4 실측](../tools/sketchup/README.md) — `persistent_id`·옵저버·인스턴싱 전부 동작.
Revit은 두 머신 모두 미설치.

**귀결**
- 지오메트리 추출을 Ruby → **C API(네이티브 확장)로 이관**하는 것이 Phase 2 첫 항목
- Ruby는 변경 감지(옵저버)와 제어만 담당
- [Enscape 분석](02-Enscape-아키텍처-분석.md) 기준 시장 1위도 호스트 5개뿐 — SketchUp 하나로 시작하는 것은 정상 범위

### ② 제품 정체성 = SketchUp 전용 시작 + 범용 프로토콜

**귀결**
- 씬 델타 프로토콜을 **SketchUp에 종속시키지 않고** 설계 (접점 옵션 S2 채택, E2는 나중에 열어 둠)
- 프로토콜은 어차피 SketchUp 때문에 필요하므로 범용 설계의 추가 비용이 거의 없음
- axia-sketch·AXiA3D는 **지금은 접점을 만들지 않습니다.** 나중에 생산자로 합류 가능
- E1(axia-sketch 크레이트 통합)은 **채택하지 않음** — IRIS 구현 언어가 Rust로 강제되고 SketchUp 경로 재사용이 사라짐

### ③ 타깃 GPU = RTX 전용 / 구축 경로 = B

근거: 소규모 팀이 1년 내 결과를 낼 수 있는 유일한 경로. Enscape형 자체 BVH 하이브리드는
그래픽스 팀의 다년 투자가 필요하며, Enscape은 RTX가 없던 시절부터 10년 가까이 쌓은 것입니다.

**대가를 명시적으로 인정합니다**: 시장이 RTX 보유자로 제한됩니다. Enscape이 내장 그래픽까지
커버하는 것과 대비되며, 이는 [02번 문서](02-Enscape-아키텍처-분석.md)가 기록한 모순을
**품질·속도 쪽으로 해소한 결정**입니다.

**귀결**
- 스택: **Donut + RTXDI(직접광) + SHaRC 또는 NRC(간접광) + NRD(디노이즈) + Streamline/DLSS(업스케일)**
- **RTXPT 샘플이 출발점** (자료집 19장 첫 줄)
- **AMD Brixelizer GI 경로 폐기** — 폴백을 안 하므로 이중 GI 아키텍처 부담이 사라짐
- **최소 사양 = 하드웨어 RT 보유 GPU** (RTX 20 시리즈 이상)
- ⚠ **AI-00-002(GTX 1060)의 폴백 검증기 역할이 소멸했습니다.** 남는 용도는 Enscape 2.5 동작 관찰뿐입니다 — 아래 "개발 환경" 항목을 그에 맞게 읽으십시오
- SHaRC는 벤더 무관이라 나중에 AMD/Intel 확장 시 일부 완충이 됩니다

### ④ 라이선스 = 클로즈드 상용

**귀결 — 즉시 영향 있는 것들**

| 대상 | 결정 |
|---|---|
| **IfcOpenShell** (LGPL-3.0) | **회피.** 대신 **web-ifc**(Apache 계열) 채택 검토 — 자료집 16장 권고 |
| **OpenCASCADE** (LGPL) | IfcOpenShell이 내부적으로 사용. web-ifc는 미사용 → web-ifc를 택할 또 하나의 이유 |
| **Blender / Cycles** (GPL) | **사용 불가** |
| **Qt** (LGPL) | 동적 링크 조건 준수 또는 상용 라이선스 구매. 대안: Slint, CEF/WebView2 |
| **NVIDIA SDK** (RTXPT·NRD) | **확인 완료 (2026-09-07)** — NVIDIA RTX SDKs LICENSE. **포크·수정·파생 저작물 생성 가능**, 오브젝트 코드로 배포 가능. 조건은 [06번 2절](06-Phase1-계획.md) |
| **Donut** | **MIT — 확인 완료.** 제약 없음 |
| Poly Haven / ambientCG | CC0 — 제약 없음 |

> **NVIDIA 라이선스 4(e)가 위 결정을 이중으로 정당화합니다.**
> 4(e)는 *"SDK가 오픈소스 라이선스의 대상이 되게 하는 방식으로 사용해서는 안 된다"* 고
> 규정합니다. IfcOpenShell(LGPL)을 피한 원래 근거는 "동적 링크 조건 부담"이었지만,
> 이제 **NVIDIA 라이선스 위반 위험**이 근거로 추가됩니다. 같은 이유로 Qt LGPL 경로도
> 신중해야 하며 Slint·WebView2 쪽이 안전합니다.

| **`VK_NV_cluster_acceleration_structure`** (rev 4) | **RTX Mega Geometry.** 자료집 [4.1의 RTXMG](01-실시간렌더러-오픈소스-자료집.md), [8장 대규모 지오메트리](01-실시간렌더러-오픈소스-자료집.md)에 대한 하드웨어 경로 |
| **`VK_NV_partitioned_acceleration_structure`** | PTLAS — 대량 인스턴스 효율 처리 |
| **`VK_EXT_ray_tracing_invocation_reorder`** | SER. `..._MODE_REORDER_EXT`로 보고 = **실제 재정렬 동작**. 패스트레이싱 발산 광선 성능에 유의미 |
| `VK_KHR_ray_tracing_position_fetch` | BLAS에서 정점 위치 직접 read — 어트리뷰트 버퍼 중복 제거 |
| `VK_NV_ray_tracing_linear_swept_spheres` | Blackwell 신규 프리미티브 |
| `VK_NV_ray_tracing_motion_blur` | 모션 블러 |

> **왜 중요한가.** 자료집 0장은 네 축 중 **③ 대규모 씬 처리를 난이도 "상"**으로 잡았습니다.
> BIM 모델이 수천만 폴리곤 + 수만 오브젝트이기 때문입니다([과제 4 실측](../tools/sketchup/README.md)의
> SketchUp 모델도 인스턴스 1,699개였고 실제 BIM은 훨씬 큽니다).
> **그 문제에 보급형 5060 Ti가 하드웨어 클러스터 가속 구조를 갖고 있습니다.**
> 소프트웨어로 Nanite류를 재구현하는 대신 이 경로를 쓸 수 있다는 뜻이며,
> 경로 B 선택의 근거가 하나 늘었습니다.

> ⚠ **환경변수 전파 주의.** 설치 관리자가 `VULKAN_SDK`·`VK_SDK_PATH`·`PATH`를 레지스트리에
> 정확히 등록하지만, Windows는 **이미 실행 중인 프로세스에 전파하지 않습니다.**
> 설치 전부터 떠 있던 터미널·IDE·Claude Code는 옛 환경을 그대로 씁니다.
> `glslc`를 못 찾거나 CMake가 Vulkan을 못 찾으면 **재시작하십시오.**

> **CMake 버전 주의.** 번들 CMake는 4.2.3입니다. CMake 4.x는 `cmake_minimum_required(VERSION 3.5 미만)` 지원을 삭제했고 nvpro-samples와 일부 NVIDIA SDK가 아직 구버전 선언을 쓰고 있어 **configure 단계에서 그대로 실패할 수 있습니다.** 실패 시 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`로 우회하거나 CMake 3.31 계열을 별도 설치하십시오.

##### ⚠ 04번 문서의 NRD 비교에 단서가 붙습니다

NRD-Sample README에 NVIDIA가 직접 이렇게 적어 두었습니다.

> *"NRD와 DLSS-RR은 오늘날 매우 경쟁적이며, **효과적인 비교에는 NRD의 'SH'
> (구면조화) 모드 활성화가 필요하다**"*

그런데 **NRD-Sample의 기본값은 `NRD_MODE NORMAL`** 이고(`Shaders/Shared.hlsli:16`),
**RTXPT도 `REBLUR/RELAX_DIFFUSE_SPECULAR` 를 쓰며 `_SH` 변형이 아닙니다**
(`Rtxpt/Sample.cpp:2571`).

즉 [04번 문서 5절](04-RTXPT-실측.md)의 *"DLSS-RR이 NRD 경로보다 빠르고 정확하다"*는
**"RTXPT v1.8.1 기본 설정 기준"** 으로는 유효하지만, **"NRD의 최선 대 DLSS-RR"**
은 아닙니다. NVIDIA 자신의 샘플들이 기본값을 공정 비교 설정으로 두지 않았습니다.

파이프라인 결정(DLSS-RR)은 여전히 방어됩니다 — 속도·정확도 양쪽에서 이겼고 그것이
RTXPT의 기본값이기도 합니다. 다만 **근거의 범위가 제가 처음 서술한 것보다 좁습니다.**

## 주의사항

- **한글 로케일(CP949) 빌드 실패** — MSVC가 UTF-8 소스의 비ASCII 주석을 못 읽어 `C4819`→`C2220`으로 죽습니다. `-utf-8` 플래그로 해결. **서구권 오픈소스를 빌드할 때마다 재현됩니다**
- **Git Bash 경로 변환** — MSYS가 `/utf-8`을 `C:/Program Files/Git/utf-8`로 번역합니다. 대시 형식 `-utf-8` + `MSYS_NO_PATHCONV=1`
- **`CMAKE_*_FLAGS`를 덮어쓰지 말 것** — CMake의 MSVC 기본값(`/EHsc` 등)이 통째로 사라집니다. 상세는 [04번 문서 1.2절](04-RTXPT-실측.md)
- **빌드 로그는 파일로 온전히 받을 것** — `| tail`로 파이프하면 cmake 실패가 파이프라인 종료 코드에 가려집니다
- **CMake 4.x 호환성** — RTXPT에서는 발생하지 않았으나(미사용 경로의 선언뿐) nvpro-samples에서 만날 수 있습니다. 회피: `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`
- **업스케일러 전제조건** — 모션 벡터 + 깊이 버퍼 + 지터링된 카메라. 렌더러 설계 초기부터 파이프라인에 넣지 않으면 나중에 갈아엎게 됩니다
- **라이선스 — 클로즈드 상용 확정에 따라 결정 완료.** Blender/Cycles(GPL)는 통합 불가. IfcOpenShell(LGPL-3.0)은 회피하고 **web-ifc**를 채택 검토합니다. 위 "확정 사항과 귀결 ④" 표 참조
- **5060 Ti는 보급형** — 128비트 버스입니다. 레퍼런스 장비는 아니지만, 보급형에서 개발하면 성능 목표에 정직해집니다. Enscape이 시장을 가져간 이유가 정확히 그 지점입니다
- **제품의 해자는 렌더러가 아님** — 자료집 0장 참조. 렌더링 코어는 SDK 조립이지만, CAD 라이브 링크는 참고할 오픈소스가 거의 없습니다
