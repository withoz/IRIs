## 2. IRIS 관점에서 확인된 세 가지

### 2.1 두 엔진 모두 하드웨어 레이트레이싱이 없습니다 — 그러나 결함이 아닙니다

검색 결과 RT 관련 코드는 벤더링된 opennurbs(C++)와 `xia-form/src/bvh.rs`(CPU BVH)뿐입니다.

**이는 올바른 설계입니다.** 모델러와 렌더러는 요구가 반대입니다:

- **모델러** — 드래그하는 매 프레임 지오메트리가 바뀝니다. RT를 쓰면 프레임마다 BLAS를
  재구축해야 하고 편집 반응성이 무너집니다
- **렌더러** — 지오메트리는 로드 후 고정, 카메라·조명만 움직입니다. BLAS는 한 번 짓고
  TLAS만 갱신하면 됩니다

업계 전체가 같은 구조입니다: SketchUp↔Enscape, Blender EEVEE↔Cycles, Rhino 뷰포트↔V-Ray.
**Enscape이 SketchUp 안의 뷰포트 모드가 아니라 별도 프로세스인 이유가 이것입니다.**

각 엔진의 제약을 정확히 하면:

| 엔진 | 제약 | 개선 대상인가 |
|---|---|---|
| **AXiA3D** | 브라우저에 하드웨어 RT가 **표준에 아예 없음**. Three.js를 wgpu로 바꿔도 동일 | ❌ 플랫폼 조건. 그 대가로 "설치 없이 링크로 열림"을 얻음 |
| **axia-sketch** | ① wgpu 하드웨어 RT는 실험 단계 ② **설령 지원돼도 NVIDIA SDK는 못 씀** — RTXDI·NRD·DLSS는 네이티브 Vulkan/DX12 device·queue·swapchain 핸들을 요구하는 C++ 라이브러리이고, wgpu는 바로 그 핸들을 감추는 것이 존재 이유 | ❌ 웹 타깃 때문에 wgpu 선택이 고정됨 |

### 2.2 `.skp` 직접 읽기는 두 엔진 모두 막혔습니다 — IRIS는 다른 문으로 들어갑니다

| 저장소 | 상태 |
|---|---|
| `axia-sketch/docs/skp_import_plan.md` | Trimble Developer Terms **§2.7.2** — 제3자 앱 임베드는 사전 서면 승인 필요. **계획만, 미구현** |
| `AXiA3D/web/src/import/FileImporter.ts:762` | `loadSKP()`가 **명시적으로 차단**하고 안내 메시지 표시 |

두 저장소가 **독립적으로 같은 결론**에 도달했습니다.

**그런데 그 조항이 인용한 예외가 "사용자가 활성 SketchUp 라이선스를 보유한 확장(extension)"입니다.**
IRIS의 라이브 링크는 정확히 그 형태 — SketchUp **안에서** 사용자 라이선스로 도는 플러그인이
지오메트리를 내보내는 구조이며, [과제 4 프로브](../tools/sketchup/README.md)가 이를 실증했습니다.

**IRIS는 두 엔진이 막힌 문(파일 직접 읽기)이 아니라 다른 문(인프로세스 확장) 앞에 서 있습니다.**

> ⚠ `AXiA3D/README.md`의 기능 목록에 `Import: ... SKP`가 적혀 있으나 코드는 차단합니다.
> 문서와 구현이 어긋납니다.

### 2.3 BIM 임포트 자산이 이미 상당합니다

| 저장소 | 자산 |
|---|---|
| AXiA3D | `axia-ifc` 11,809 LOC · `axia-foreign`(STEP/IGES 파서) 5,981 LOC · OpenCascade WASM 연동 |
| axia-sketch | `axia-io` 14,139 LOC — IFC·DWG·DXF·glTF·STEP·STL·3DM·OBJ·xref 캐시 |

자료집 10장이 "가장 어려운 축"이라 한 영역입니다.

## 3. 접점 옵션

만나는 지점은 **두 층**입니다.

```
[데이터 생산자]          [전송 계층]            [소비자]
SketchUp ──┐
axia-sketch ├──→  ??? 프로토콜/포맷  ──→  IRIS 렌더러
AXiA3D ────┤                               (Vulkan + RTX SDK)
IFC 파일 ──┘
```

- **데이터 계층** = 무엇을 주고받는가 (지오메트리·머티리얼·변환·카메라·델타)
- **전송 계층** = 어떻게 건네는가 (같은 프로세스 / IPC / 파일)

### 3.1 SketchUp ↔ IRIS

SketchUp은 닫힌 외부 앱이고, IRIS는 자체 Vulkan 디바이스·창이 필요하므로
**반드시 별도 프로세스**입니다. 질문은 "SketchUp 안에서 무엇이 데이터를 퍼내는가"입니다.

| # | 방식 | 추출 속도 | 라이브 링크 | 라이선스 |
|---|---|---|---|---|
| **S1** | Ruby 확장만 | **75k tri/s (실측)** | O | 안전 |
| **S2** | Ruby + 네이티브 확장 DLL | 미측정 | O | 안전 |
| S3 | 중간 포맷 export → import | — | **X** | 안전 |
| S4 | `.skp` 직접 파싱 | — | X | **차단** |

**S2가 Enscape·V-Ray·Twinmotion이 쓰는 방식입니다.** Ruby가 옵저버·UI·제어를 맡고
지오메트리 추출 핫루프만 네이티브로 내립니다. 실측 75k tri/s(1000만 삼각형에 133초)가
그 이관의 근거입니다.

> ⚠ **미검증**: 네이티브 Ruby C 확장에서 *어떤 API 표면으로* 지오메트리를 뽑는지는
> 아직 확인하지 않았습니다. SketchUp C SDK는 본래 `.skp` 파일 입출력용이라, 인프로세스
> 확장에서 쓸 수 있는 경로가 정확히 무엇인지 별도 검증이 필요합니다.

전송 계층: **T1 공유 메모리**(대량 지오메트리 최적) / **T2 로컬 소켓·네임드 파이프**(델타에 충분) /
T3 임시 파일(프로토타입용).

### 3.2 엔진 ↔ IRIS

| # | 방식 | 결합도 | 장점 | 걸림돌 |
|---|---|---|---|---|
| **E1** | IRIS를 axia-sketch 워크스페이스 **크레이트**로 (`ash` 직접) | 최고 | 씬 무복사 접근, 단일 바이너리 | NVIDIA SDK가 C++ → Rust FFI 부담. wgpu·Vulkan 디바이스 공존 |
| **E2** | **별도 프로세스 + 공통 프로토콜** | 중간 | **SketchUp과 같은 프로토콜 재사용**. IRIS 언어 자유 | 직렬화 비용, 프로세스 관리 |
| **E3** | 파일 포맷 경유 (glTF / **USD** / `.axia`) | 낮음 | 표준 활용. USD면 Hydra 델리게이트로 Maya·Houdini·3ds Max·Omniverse 자동 연결 | 라이브 링크 아님 |
| **E4** | 만나지 않음 | 없음 | 각자 최적화 | 중복 투자 |

**AXiA3D 추가 제약**: 브라우저 빌드는 IRIS와 만날 수 없습니다(로컬 프로세스도 Vulkan도 없음).
**Tauri 데스크톱 셸을 통해서만** 가능하며, 이는 AXiA3D의 핵심 가치("설치 없이 링크로 열림")와
다른 축입니다.

### 3.3 관통하는 관찰 — 프로토콜이 곧 접점

**S2와 E2는 같은 프로토콜을 씁니다.**

```
SketchUp 확장 ──┐
axia-sketch ────┼──→ [씬 델타 프로토콜] ──→ IRIS
AXiA3D(Tauri) ──┤
IFC 임포터 ─────┘
```

그 프로토콜의 요구사항은 **이미 실측으로 확보되어 있습니다**:

| 요구사항 | 실측 근거 (과제 4) |
|---|---|
| 안정적 ID 기반 델타 (추가/수정/삭제) | `persistent_id` O |
| 정의/인스턴스 분리 (BLAS/TLAS 대응) | 재사용률 4.00 |
| 머티리얼 참조 + 텍스처 경로 | 41종 / 텍스처 15 |
| 정점·법선·UV | 전부 확보, 실패 0 |
| **삭제 시 자체 ID 매핑 테이블** | `onElementRemoved`가 entityID만 전달 |

[`tools/sketchup/iris_probe.rb`](../tools/sketchup/iris_probe.rb)가 출력하는 JSON 스키마가
사실상 **이 프로토콜의 초안**입니다.

**E1(크레이트 통합)을 택하면 이 재사용이 사라집니다** — axia-sketch 전용이 되고
SketchUp 경로는 따로 만들어야 합니다.

## 4. 결정에 필요한데 아직 없는 정보

1. **네이티브 확장의 실제 추출 속도** — S1→S2 이관 효과가 10배인지 100배인지에 따라
   아키텍처가 달라집니다. **검증 가능**
2. **IRIS 구현 언어 (C++ / Rust)** — NVIDIA SDK가 전부 C++이라 이것이 E1/E2 선택을
   사실상 결정합니다
3. **제품이 몇 개인가** — IRIS가 SketchUp용 단일 제품인지, 엔진들의 공통 렌더링
   백엔드인지. **기술이 아니라 사업 판단이며, 나머지를 좌우합니다**
