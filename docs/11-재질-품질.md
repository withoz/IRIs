# 11. 재질 품질 — Enscape 와의 차이를 줄이는 계획

> 등급: **측정** = 이 모델·이 코드에서 직접 확인 · **추론** = 코드를 읽고
> 유도 · **가정** = 근거 없음, 확인 대상

## 11.1 왜 이 문서인가

"Enscape 와 우리 앱은 재질에서 품질 차이가 많이 난다"는 보고를 받았습니다.
차이를 **느낌으로 두지 않고** 어디서 벌어지는지 구간을 나눠 적습니다.

재질 화면은 세 곳에서 망가질 수 있고, 고치는 값도 비용도 완전히 다릅니다.

```
 SketchUp/Enscape ──[프로브]──> .irisb ──[SceneBuilder]──> Donut Material
                                                                │
                                                     [ImportFromDonut]
                                                                ▼
                                                          PTMaterial ──> GPU
```

① 호스트가 주는데 **안 싣는 것**
② 실어 보냈는데 **안 쓰는 것**
③ 아무도 안 주는 것 — **우리가 정해야 하는 것**

아래는 셋을 갈라 놓은 것입니다.

## 11.3 1순위 — 지금 **틀린** 것

버그에 가깝습니다. 값을 잘 고르는 문제가 아니라 정보를 버리고 있습니다.

### (a) 알파 컷아웃이 사라집니다 — 나뭇잎·난간·타공판

**측정.** 세종 모델이 내보낸 텍스처 16개 중 12개가 알파 채널을 가졌고,
그중 하나(`mat_285.png`, 617×490)는 **픽셀의 38.6%가 완전 투명**합니다.

그런데 `SceneBuilder::BuildMaterials` 의 분기는 이렇습니다:

```cpp
const bool glass = authorGlass || (alpha < 0.999f && !hasTexture);
...
else m->domain = (alpha < 0.999f) ? AlphaBlended : Opaque;
```

텍스처 재질의 `alpha` 는 SketchUp 의 **재질 알파**이고, 컷아웃 PNG 는
재질 알파가 1.0 입니다. 그래서 `domain = Opaque` → RTXPT 가
`EnableAlphaTesting = false` → **알파 채널을 통째로 버립니다.** 구멍이
막힌 채로 그려집니다.

세종 모델에는 `Perforated Panel2`(타공 금속 패턴 텍스처)가 있고, 이전
조사에서 "알파 1.000 · 불투명 — 문제 없음"이라고 적었습니다. **그 판정이
틀렸습니다** — 타공판은 구멍이 있어야 합니다.

#### 한 일 (2026-09-12)

**호스트 절반은 끝났고 시험까지 마쳤습니다. 엔진 절반에서 막혔습니다.**

##### 프로브가 알파를 **잽니다** — 읽는 법은 맞춰서 알아냈습니다

처음에는 `ImageRep#resize(64,64)` 로 줄여 표본을 보려 했습니다. 거의 모든
텍스처에서 값이 안 나왔습니다. 짐작하지 않고 **정답이 있는 텍스처 하나로**
맞췄습니다 — `Perforated Panel2`(617x490), 내보낸 PNG 를 따로 디코딩해
38.6% 투명임을 미리 알고 있었습니다(`iris_texalpha_diag.rb`):

| 확인한 것 | 결과 |
|---|---|
| `ImageRep#resize` | **없습니다** (SketchUp 2026). 첫 판이 여기서 통째로 막혔습니다 |
| 있는 메서드 | bits_per_pixel, color_at_uv, colors, data, height, load_file, row_padding, save_file, set_data, size, width |
| `#data` | 1.2 MB 를 **0.8 ms** 에 줍니다 (`#colors` 와 달리 객체를 안 만듭니다) |
| 알파 위치 | **픽셀당 4바이트 중 4번째**. 3번 바이트 = 33.4%·최솟값 0 (정답 38.6%), 0번 바이트 = 100%·최솟값 53 (색) |

표본은 **행 단위**로 뽑습니다. 일정 간격으로 픽셀을 건너뛰면 타공판·격자
같은 규칙적인 무늬에서 간격이 행 너비와 맞아떨어져 같은 자리만 훑습니다.
행을 고르고 그 행은 전부 보면 세로 줄무늬에 안 걸립니다.

##### 재는 것이 왜 중요한가 — 채널만 보면 17배 과잉입니다

세종 모델 텍스처 재질 18개 실측:

```
알파 채널 있음   12개
그중 구멍 있음    1개   (Perforated Panel2, 32.5%)
나머지 11개는 최솟값 255 — 채널만 있고 전부 불투명
```

"채널이 있으면 알파 테스트"로 했으면 **12개에 애니히트 셰이더가 붙고 BLAS
불투명 최적화를 잃었을 것**입니다. 실제로 필요한 것은 1개입니다.

##### 배선과 시험

- `iris_probe.rb` → 매니페스트 `texture.alpha = {channel, min, holes}`
- `IrisbReader` → `Texture::alphaChannel/alphaMin/alphaHoles`,
  판정은 `Texture::NeedsAlphaTest()` 한곳에. **못 잰 것(음수)과 '구멍
  없음(0)'을 구별**합니다 — 0을 기본값으로 두면 큰 텍스처가 전부
  "구멍 없음"이 됩니다.
- `SceneBuilder` → `MaterialDomain::AlphaTested`, `alphaCutoff = 0.5`
- 시험 41개 통과. 판정표(7가지)와 **합성 배선 씬의 파싱**(mat_leaf /
  mat_tile / mat_bigtex)을 둘 다 못박았습니다. 옛 `.irisb` 는 항목이
  없으므로 그대로 꺼집니다 — 뒤로 호환됩니다.
- 렌더러 로그: `IRIS: 텍스처 16개 · 그중 알파 컷아웃 1개 (프로브가 못 잰 것 0)`

#### 도중에 렌더러가 죽었습니다 — 원인은 nvrhi 의 널 검사 누락

`MaterialDomain::AlphaTested` 를 만드는 재질이 씬에 하나라도 들어가면
RTXPT 가 씬 적용 직후 세그폴트했습니다(종료 코드 139).

**통제 시험으로 먼저 갈랐습니다.** 같은 빌드·같은 모델에서, 화면 한가운데
면에 `Perforated Panel2` 를 칠했다 되돌리는 것만 바꿨습니다
(`iris_cutout_test.rb`, 카메라 광선으로 보이는 면을 고릅니다):

| 칠함 | 재질 수 | 결과 |
|---|---:|---|
| 예 | 79 | **죽음** (139) |
| 아니오 | 78 | 65.7 FPS 로 정상 |

##### 로그로는 못 찾았습니다 — 스택을 받아야 했습니다

의심한 자리를 하나씩 로그로 찍었는데 **전부 정상**이었습니다:
`UpdateSubInstanceData` 의 알파 분기(디스크립터 583·TexCoord1 있음·
퍼뮤테이션 있음) · OMM 준비 경로(CPU 이미지·GPU 텍스처 유효) ·
셰이더 퍼뮤테이션 첨자와 `ShaderLibrary`. D3D12 디버그 계층과 NVRHI 검증
계층을 켜도 **아무 메시지 없이** 죽었습니다.

이 머신에는 cdb·WinDbg 가 없습니다. 그래서 **프로세스가 스스로 자기
스택을 적게** 했습니다(`Rtxpt/Iris/IrisCrashReport.h` — 헤더 하나,
`SetUnhandledExceptionFilter` + `StackWalk64` + `SymFromAddr`,
Debug 의 assert 도 같은 파일로 보냅니다). Release PDB 가 있어 줄 번호까지
나옵니다. **한 번에 나왔습니다:**

```
접근 위반: 읽기 주소 0x0
 #00 nvrhi::d3d12::fillAsInputDescForPreBuildInfo  (d3d12-raytracing.cpp:776)
 #01 nvrhi::d3d12::Device::GetAccelStructPreBuildInfo
 #02 nvrhi::d3d12::Device::createAccelStruct
 #03 OmmBuildQueue::BuildBLASWithOMM               (OmmBuildQueue.cpp:389)
 #06 OmmBaker::BuildOpacityMicromaps
 #07 Sample::Render
```

##### 원인

`fillD3dGeometryOMMLinkageDesc`(d3d12-raytracing.cpp:650)에 널 검사가
없습니다:

```cpp
outLinkage.OpacityMicromapArray = triangles.opacityMicromap->getDeviceAddress();
```

같은 파일 665줄, 같은 일을 하는 NVAPI 경로(`fillOmmAttachmentDesc`)는
검사합니다 — **한쪽만 빠진 것입니다.** 그리고 호출부(772~777)는 지오메트리
**하나라도** OMM 이 있으면 **전부**에 대해 링키지를 채웁니다.

즉 **한 메시 안에 OMM 있는 것과 없는 것이 섞이면** 없는 쪽에서 죽습니다.
RTXPT 기본 씬에는 없는 조합인데, **SketchUp 정의는 재질 버킷이 여럿**이라
알파 테스트와 불투명이 한 메시에 섞이는 것이 보통입니다.

##### 고침

기본은 **우리 쪽 가드**입니다(`OmmBaker.cpp`, `CreateOpacityMicromaps`):
섞인 메시는 OMM 을 건너뜁니다. OMM 은 **가속 구조 최적화**일 뿐이고 알파
테스트 자체는 애니히트 셰이더로 돌므로 화면은 맞습니다 — 느려질 뿐입니다.

제대로 된 고침은 nvrhi 한 줄이고 패치로 남겼습니다
(`tools/rtxpt/patches/nvrhi-omm-linkage-null.patch`). nvrhi 는 **중첩
서브모듈**(RTXPT → Donut → nvrhi)이라 그 수정은 다른 체크아웃으로 따라가지
않습니다 — 머신이 둘이므로 기본을 가드로 둔 이유입니다.

##### 확인 — 첫 A/B 는 **무효였습니다**

설정을 끄고 다시 보내 견줬더니 두 장이 똑같았습니다. 픽셀만 봤으면
"효과 없음"으로 결론 낼 뻔했는데, 로그가 막았습니다:

설정은 **씬을 만들 때** 읽히는데, 바이트가 같아 브리지가 걸렀습니다.
끈 설정이 적용된 적이 없었던 것입니다. 렌더러를 껐다 켜고 다시 했습니다:

|---|---|
| 끔 | 빛이 전혀 안 통하는 **검은 판**. 무늬만 인쇄돼 있습니다 |
| 켬 | **구멍마다 빛이 들어오는 스크린** |

> 화면이 안 바뀐 것이 "효과 없음"이 아니라 "안 보냈음"일 수 있습니다.

`IRIS 설정 > Textures > Texture alpha cutout`. 실제로 구멍이 있는 텍스처만
알파 테스트로 갑니다(프로브가 잽니다). 세종 모델에서는 18개 중 1개입니다.

### (b)(c) 평면 유리를 **입체**로 굴절시켰습니다 — ✅ 고쳤습니다

**측정.** `PTMaterial::ThinSurface` 는 기본 `false` 였고, 우리는 한 번도
건드리지 않았습니다. 셰이더에서 이 깃발은 굴절률을 바꿔치기합니다:

```hlsl
// BxDF.hlsli:410
float actualEta = (isThinSurface && !isReflection) ? (1.0f) : (eta);
```

그리고 `PathTracerNestedDielectrics.hlsli` 에서 thin 이 아닌 표면은
**중첩 유전체 스택에 들어갑니다.** 건축 유리는 거의 언제나 **단면(한 장의
면)** 이라, 두께가 없는 면을 "들어가서 안 나오는 매질"로 다루면 굴절·흡수가
어긋납니다. Enscape 가 `IsSolidGlass` 라는 깃발을 따로 두는 이유가 이것인데,
**우리는 그 값을 "유리인가" 판정에만 쓰고 버리고 있었습니다.**

굴절률도 같은 처지였습니다. `MaterialPbr::ior` 까지 파이프로 실어 놓고
`ImportFromDonut` 에서 주석 처리되어(Donut 의 `Material` 에 필드가 없습니다)
**전부 1.5** 가 됐습니다.

#### 화면 — 예측대로였습니다

같은 카메라·같은 **고정 노출**·같은 모델에서 깃발 하나만 바꿨습니다.
세종 모델 커튼월(유리 9개, Enscape 설정은 0개):

| | 화면 |
|---|---|
| 덩어리 (지금까지) | 유리가 **하얗게 타서 아무것도 안 비칩니다** |
| 단면 (고친 뒤) | **하늘→지면 그라데이션이 그대로 비칩니다** |

광선이 매질에 들어가서 안 나오던 것입니다. 바깥이 통째로 사라졌습니다.

#### 배선 — Donut 에 칸이 없는 값을 나르는 길

`SceneBuilder` 는 RTXPT 타입을 몰라야 하므로 **힌트만 내고 적용은 호출자가**
합니다. 인스턴스 재질과 같은 방식이고, 결합이 `IrisScene.cpp` 한 곳에만
남습니다:

```
SceneBuilder::MaterialHints {thinSurface, ior}
   -> SetMaterialHintApplier (IrisScene.cpp)
      -> MaterialEx::IrisThinSurface / IrisIoR
         -> MaterialsBaker::ImportFromDonut -> PTMaterial
```

판정은:

```cpp
// Enscape 가 말했으면 그 값이 이깁니다 — false 도 저작자의 답입니다.
hints.thinSurface = ePbr ? !sm.pbr.solidGlass : m_glassThinDefault;
```

굴절률은 1.0~3.0 만 받습니다. Enscape 의 **0 은 미지정**이라 그대로 두면
엔진 기본값(1.5, 판유리)이 남습니다.

#### 설정

`IRIS 설정 > Glass > Thin glass (single-sided)`, **기본 켬**. Enscape 값이
있으면 그쪽이 이기고, 없을 때만 이 값입니다.

> **등급.** "저작자가 말 안 하면 단면"은 아직 **가정**입니다. 커튼월·창·
> 난간이 단면 모델링인 것은 맞지만 모델 통계로 센 적은 없습니다. 유리
> 탁자처럼 진짜 덩어리인 프로젝트에서는 꺼야 합니다 — 그래서 밖으로 뺐습니다.

#### 확인 절차 (1번에서 배운 것을 적용했습니다)

1. **고정 노출**로 견줬습니다(자동 노출 끔).
2. A/B 사이에 **렌더러를 껐다 켰습니다** — 설정은 씬을 만들 때 읽히는데
   바이트가 같으면 브리지가 "같은 씬"으로 걸러 버립니다(1번에서 당했습니다).
3. **바뀐 것이 실제로 건너갔는지 로그로 먼저 확인**했습니다:

```
A  IRIS: 유리 — 단면 0개 · 덩어리 9개 · 저작자 굴절률 0개
B  IRIS: 유리 — 단면 9개 · 덩어리 0개 · 저작자 굴절률 0개
```

4. 파이프가 값을 나르는지는 합성 배선 씬으로 못박았습니다
   (`mat_glass_thin` / `mat_glass_solid`(1.52) / `mat_water`(1.33), 시험 48개).

## 11.4 2순위 — **있는 데이터**를 다 쓰기

Enscape 설정이 있는 7~17% 에만 듣지만, 그 재질들이 보통 화면에서 크게
차지합니다(바닥·잔디·외장).

### (d) 범프 / 디스플레이스먼트 — 지금 표면이 완전히 평평합니다

**측정.** Enscape 의 `MaterialData` 원문(`out/sketchup/attrs_dump.txt`):

```xml
<BumpAmount>0.322603449901027</BumpAmount>
<NormalMapIntensity>0</NormalMapIntensity>
<BumpMapType>DISPLACEMENT</BumpMapType>
<BumpTexture>
  <Source>SKETCHUP</Source>
  <Filepath>C:/Users/User/AppData/Local/Temp/잔디-색상변경-3(1).jpg</Filepath>
  <IsInverted>false</IsInverted>
  <Width>0.5</Width> <Height>0.4657</Height> <Rotation>0</Rotation>
</BumpTexture>
```

잔디 재질이 범프 0.32~0.64 로 들어 있고 **높이맵은 디퓨즈와 같은 파일**
입니다. 우리는 이것을 전혀 읽지 않습니다. 잔디·아스팔트·벽돌·콘크리트가
전부 매끈한 판으로 나옵니다.

**고침**

1. `iris_enscape.rb` 가 `BumpTexture` 를 읽어 파일 경로·변환·`IsInverted`
   를 매니페스트에 싣습니다(디퓨즈 텍스처와 같은 방식으로 내보내기).
2. 높이맵 → 노멀맵 변환(Sobel). 프로브(느림)보다 **C++ 로드 때** 하는
   편이 낫습니다 — 델타 재전송에서 다시 하지 않아도 됩니다.
3. `material->normalTexture`, `normalTextureScale = BumpAmount`.
4. **탄젠트가 없습니다.** `.irisb` 는 위치·법선·UV·인덱스만 싣습니다.
   `PTMaterial::IgnoreMeshTangentSpace = true` 로 두면 엔진이 UV 미분에서
   탄젠트를 만듭니다(측정: `MaterialsBaker.cpp:558`).
   정점에 탄젠트를 싣는 것보다 싸고, 전송량도 안 늘어납니다.

`BumpMapType` 이 `NORMAL` 이면 변환 없이 그대로 노멀맵입니다.

### (e) 발광 텍스처

`SELF_ILLUMINATED` 재질은 `EmissiveStrength` 를 3,472 / 5,076 / 7,000
cd/m² 로 갖고 있고(측정), 디퓨즈 텍스처도 있습니다. 지금은 **균일한 색**
으로만 빛납니다. 텍스처가 있는 조명 패널(로고·간판)은 무늬가 사라집니다.

`emissiveTexture = baseOrDiffuseTexture` 로 두는 것만으로 대부분 해결됩니다.

### (f) 틴트 · 밝기 · 반전

`TintColor`, `ImageFade`, `DiffuseTexture/Brightness`, `IsInverted` 를
읽지 않습니다. 저작자가 Enscape 에서 텍스처를 어둡게/밝게 맞춰 놓았다면
우리 화면만 다릅니다. 싼 항목입니다.

`Specular`(0.5 기준) 는 Donut 금속-거칠기 모델에 대응 칸이 없어
**지금은 개수만 셉니다**(`stats.specularOverrides`). 그대로 둡니다.

## 11.5 3순위 — **없을 때** 잘 추측하기 (재질의 80~90%)

여기가 제일 큽니다. 그리고 제일 위험합니다.

### (g) `roughness 0.5 · metalness 0` 고정을 버립니다

```cpp
// SceneBuilder.cpp:227
m->metalness = 0.0f;
m->roughness = 0.5f;
```

**모든 재질이 같은 광택입니다.** 아스팔트도, 유리 난간도, 스테인리스
손잡이도, 잔디도 0.5. 화면 전체가 같은 플라스틱처럼 보이는 주된 이유가
이것이라고 봅니다(**추론** — 아직 A/B 하지 않았습니다).

Enscape 도 추측하지만 더 잘합니다. 우리가 쓸 수 있는 단서:

- **이름** — `[Asphalt New]`, `[Granite Light Gray]`, `세라믹 판넬2`,
  `Perforated Panel2`. SketchUp 기본 재질은 영어 이름이 규칙적입니다.
- **텍스처 통계** — 평균 밝기·채도·대비·공간 주파수. 아스팔트와 잔디는
  통계가 다릅니다.
- **색만 있는 재질** — 도장으로 보고 0.4~0.6 이 무난합니다.

> ⚠ **지난번 실수를 반복하기 좋은 자리입니다.** "큰 면만 유리로 본다"는
> 규칙은 데이터가 깨끗하게 갈려서 그럴듯했지만 램프 렌즈를 깨뜨렸을
> 것입니다(09번 8-i). 그래서 이번에는 **규칙을 넣을 때 세 가지를 같이**
> 넣습니다:
>
> 1. 기본값은 **보수적으로** — 애매하면 지금 값(0.5)을 유지
> 2. **사용자가 덮어쓸 수 있게** (11.6)
> 3. **어떤 규칙이 왜 걸렸는지 로그로** — "재질 12개가 이름 규칙으로
>    아스팔트 판정(거칠기 0.9)" 처럼

### (h) 텍스처에서 범프 유도

Enscape 가 `BumpTexture` 에 디퓨즈를 그대로 넣는 것과 같은 수법입니다.
텍스처가 있는 재질에 약한 범프(0.1~0.2)를 자동으로 주면 평평함이 크게
줄어듭니다. **기본은 꺼 두고** IRIS 설정으로 뺍니다 — 잘못 걸리면
전체가 지저분해집니다.

## 11.6 4순위 — 사용자가 고칠 수 있게 (**엔진에 이미 있습니다**)

**측정.** RTXPT 에는 재질 편집기와 영구 저장이 이미 들어 있습니다:

- `PTMaterial::EditorGUI(...)` — 거칠기·금속성·IoR·ThinSurface·범프 등
- `Scene > Materials > Advanced > Save all` (`MaterialsBaker::SaveAll`)
- `MaterialsBaker::Load(modelFileName, name)` — 저장된 JSON 을 찾아 복원
- `Assets/Materials/` 에 예제 497개

### 덮어쓰기 조사 (2026-09-12) — **총**이고, **영구**입니다

```cpp
// MaterialsBaker.cpp
std::shared_ptr<PTMaterial> loaded = Load(material->modelFileName, material->name);
if (loaded != nullptr) materialEx->PTMaterial = loaded;   // ← 우리 값 전부 무시
else                   ImportFromDonut(*material);
```

읽기만으로는 "설마" 싶어 **직접 심어 봤습니다.** 세종 모델의 커튼월
(`[Translucent Glass Gray]3`) 이름으로 파일을 하나 두고, 안에는 불투명한
빨강을 적었습니다. 호스트는 그대로 **회색 반투명 유리**를 보냅니다.

> 결과: 커튼월이 **불투명한 빨강**이 됐습니다. 색·거칠기·투과·도메인까지
> 전부 파일 것으로 바뀌었고, 다시 동기화해도 그대로였습니다.

즉 **사용자 편집이 이깁니다.** 그것이 엔진의 설계이고, 재질 편집기가
있으려면 그래야 합니다. 문제는 그것이 **조용하다**는 것이었습니다.

### 찾은 위험 셋

**(1) 모델을 안 가렸습니다.** 우리는 `modelFileName` 을 비워 두고
있었습니다. 그러면 저장 파일이 `.<재질>.material.json` 이 되고,
**모든 SketchUp 모델이 이름만 같으면 같은 파일을 씁니다.**
`재질1`·`IRIS_default` 처럼 흔한 이름에서 바로 부딪힙니다.

→ 고쳤습니다. 모델(저장 경로, 없으면 제목)을 실어 이름이 이렇게 됩니다:

```
20260912_세종 자동차관련시설 멀티브랜드.[Translucent Glass Gray]3.material.json
```

`m_materialsSceneSpecializedPath` 로는 못 가립니다 — 그 폴더 이름은 씬
파일명에서 오는데 우리는 **언제나 `IRIS live`** 이고, 게다가 경로들이
`if (m_mediaPath == "")` 안에서 **프로세스당 한 번만** 정해집니다.

**(2) 덮어쓰기가 조용했습니다.** 몇 달 전에 저장해 둔 파일 하나가 남아
있으면, 사용자가 SketchUp 에서 재질을 고쳐도 화면이 안 바뀝니다. 이유를
알 방법이 없었습니다.

→ 고쳤습니다:

```
[warn] IRIS: 저장된 재질 파일 1개가 호스트 값을 덮었습니다 —
       'E:\iris-ext\RTXPT\Assets\Materials'.
       호스트 값으로 되돌리려면 그 파일을 지우십시오.
```

**(3) 텍스처 경로가 낡습니다** — 아직 안 고쳤습니다.

저장 파일은 텍스처를 `Assets` 기준 상대경로로 적습니다
(`PTTexture::InitFromLoadedTexture` → `std::filesystem::relative`).
우리 텍스처는 `out/sketchup/textures/<모델>/mat_<entityID>.png` 이고,
**`entityID` 는 지속되지 않습니다** — SketchUp 이 그래서 `persistent_id` 를
따로 둡니다. 파일을 다시 열면 같은 재질이 다른 번호를 받습니다.

즉 텍스처 있는 재질을 저장하면 **그 순간의 번호가 파일에 박힙니다.**
다음에 열면 없는 파일을 가리키거나, 더 나쁘게는 **다른 재질의 그림**을
가리킬 수 있습니다.

→ 다음 판의 후보: IRIS 재질은 저장할 때 텍스처를 빼거나(스칼라만),
   내보내기 이름을 `persistent_id` 기준으로 바꿉니다.

### 되돌리기 단추 — ✅ 만들었습니다

`IRIS 설정 > Saved material overrides`.

```
덮어쓰기가 없을 때   None - SketchUp values are in use.
있을 때 (주황색)     2 saved file(s) are overriding SketchUp
                    [ Delete overrides for this model ]
```

**범위를 좁혔습니다.** 이름으로 훑지 않고, **지금 씬에 실제로 있는
재질**의 저장 경로만 봅니다(`MaterialsBaker::IrisOverrideFiles`). 그래서
배포된 예제 497개나 다른 모델의 저장본은 건드리지 않습니다 — 시험에서
심은 2개만 지워지고 497개는 그대로였습니다.

지우기 전에 확인 대화상자가 뜨고, 지울 파일 목록(최대 8개)과 "되돌릴 수
없습니다"를 보여 줍니다.

#### 지우기만으로는 부족했습니다

처음 만들었을 때 대화상자에 "다시 보내면 호스트 값으로 돌아갑니다"라고
적었는데, **거짓말이었습니다.** 브리지가 같은 씬을 지문으로 걸러 냅니다:

```
IRIS 링크: 같은 씬이 다시 왔습니다 — 무시합니다
```

씬 바이트는 한 글자도 안 바뀌지만 **해석이 달라져야 하는** 경우입니다.
`IrisBridge::ForgetLastScene()` 을 만들어 지우기와 함께 부릅니다. 끝까지
확인했습니다:

```
1  [warn] 저장된 재질 파일 1개가 호스트 값을 덮었습니다
2  [info] 덮어쓰기 1개를 지웠습니다
3  [info] IRIS 링크: 씬 수신 121367240 bytes     ← 같은 씬인데 받아들였습니다
4  두 번째 구축에서 덮어쓰기 경고: 0개            ← 호스트 값이 돌아왔습니다
```

> **교훈.** UI 에 적은 안내 문구도 **확인 대상**입니다. "이렇게 하면
> 됩니다"라고 적어 놓고 실제로는 안 되는 것이 제일 나쁩니다.

#### 대화상자의 한글이 네모로 나왔습니다 — ✅ 고쳤습니다

되돌릴 수 없는 동작을 확인하는 자리에서 **무엇을 지우는지 읽을 수
없었습니다.** 한국어 AEC 도구로는 그대로 둘 수 없어 바로 고쳤습니다.

원인을 찾는 데 세 번 걸렸습니다. 순서대로 적습니다 — 앞의 둘은 **틀린
추측**입니다:

| 시도 | 결과 |
|---|---|
| ① 글꼴을 맑은 고딕으로 교체 | 글꼴은 바뀌었는데 **여전히 네모** |
| ② `path::string()`(CP949) → `u8string()`(UTF-8) | **여전히 네모** |
| ③ **글리프 범위**를 줌 | **나왔습니다** |

ImGui 1.92 는 글리프를 필요할 때 굽고 `GlyphRanges` 는 `*LEGACY*` 로
표시돼 있습니다. 그래서 ①만으로 될 줄 알았는데, **이 백엔드가 구식
정적 아틀라스를 씁니다** — `imgui_nvrhi.cpp` 가 `GetTexDataAsRGBA32()` 를
부르고 `ImGuiBackendFlags_RendererHasTextures` 를 세우지 않습니다. 그
경로에서는 미리 구울 글리프를 알려 줘야 합니다.

Donut 의 `RegisteredFont` 로는 범위를 줄 수 없습니다 — 그 코드가
`ImFontConfig` 를 고정합니다. Donut 은 **중첩 서브모듈**이라 고쳐도 다른
체크아웃으로 안 따라갑니다(nvrhi 때와 같은 문제). 그래서 **우리가 직접
글꼴을 만들어** 메인 UI 에 밀어 넣습니다:

```cpp
cfg.GlyphRanges = ImGui::GetIO().Fonts->GetGlyphRangesKorean();
m_koreanFont = io.Fonts->AddFontFromFileTTF("C:/Windows/Fonts/malgun.ttf", fontPx, &cfg);
...
ImGui::PushFont(m_koreanFont ? m_koreanFont : m_defaultFont->GetScaledFont());
```

포인터가 오래 사는 근거도 확인했습니다: 아틀라스를 비우는 곳은 Donut 의
`DisplayScaleChanged` 뿐인데 **SampleUI 가 그것을 오버라이드하면서 base 를
부르지 않습니다.** 이 프로세스에서 아틀라스는 한 번만 만들어집니다.

DPI 배율은 직접 곱합니다. Donut 이 자기 글꼴에만 해 주는 일이라, 안 하면
우리 글꼴만 작게 나옵니다(한 번 그렇게 나왔습니다).

대가: 맑은 고딕은 고정폭이 아니라 RTXPT 디버그 UI 의 숫자 칸이 조금
흐트러집니다. 한글을 읽는 쪽이 낫다고 봤습니다 — Windows 기본에 한글
고정폭 글꼴이 없습니다.

결과:

```
20260912_세종 자동차관련시설 멀티브랜드.박판세라믹2.material.json
20260912_세종 자동차관련시설 멀티브랜드.세종시 보도블1.material.json
```

### 남은 설계 결정

- **저장 위치.** 지금은 `Assets/Materials/` — **엔진 체크아웃 안**입니다.
  사용자 데이터가 있을 자리가 아닙니다(엔진을 다시 받으면 날아갑니다).
  `%LOCALAPPDATA%\IRIS\materials\` 로 옮기는 것이 맞지만,
  `m_materialsPath` 가 프로세스당 한 번 정해지는 구조를 건드려야 합니다.
- **무엇을 덮을 것인가.** 지금은 전부입니다. 사용자가 거칠기 하나만
  만졌는데 색·텍스처까지 그 시점 값으로 굳는 것은 라이브 링크와 어울리지
  않습니다. **바꾼 항목만** 저장하는 편이 맞다고 봅니다(추론).
- **텍스처 경로가 낡는 것**(위 (3)).

> **이제 6번(거칠기 기본값 표)으로 갈 수 있습니다.** 추측 규칙이 잘못
> 걸려도 사용자가 빠져나올 길이 생겼습니다.

## 11.7 범위 밖 — 그러나 화면에서 제일 크게 다른 것

정직하게 적습니다. 위를 다 해도 Enscape 와 나란히 놓으면 남습니다.

- **Enscape 자산(나무·사람·가구·차)** — SketchUp 에는 62~118 삼각형짜리
  껍데기만 있고 진짜 모델은 Enscape 라이브러리 안에 있습니다. 재질
  문제가 아니라 **자산 라이브러리 문제**이고, 별도 계획이 필요합니다.
- **V-Ray 재질 149개**(포르쉐 모델) — 또 하나의 PBR 출처. Enscape 다음
  후보이지만 스키마가 훨씬 복잡합니다.
- **측광 배율 5000 cd/m² = 1.0** 은 아직 `추론` 입니다(10번 10.5-1).
  발광 재질의 밝기가 통째로 여기 걸려 있습니다.

## 11.8 어떻게 확인할 것인가

이 프로젝트에서 A/B 로 두 번 헛짚었습니다. 규칙을 먼저 적습니다.

1. **자동 노출을 끕니다.** 켠 채로 견주면 밝기 차이가 재질 차이로
   보입니다(09번 8-c). 두 번 당했습니다.
2. **한 번에 한 가지만** 바꿉니다.
3. **무엇을 보면 고쳐진 줄 아는지 먼저 적습니다.** "타공판 구멍으로 뒤가
   보인다", "커튼월 너머 실내 색이 Enscape 와 같아진다" 처럼.
4. 같은 시점·같은 날짜/시각/방위. SketchUp 장면으로 고정합니다.
5. 렌더 두 장을 파일로 남깁니다 — 기억으로 견주지 않습니다.
