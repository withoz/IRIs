## 1. 무엇을 고쳤나

SketchUp 에서 면에 재질이 없으면 **상위 인스턴스의 재질**을 씁니다.
같은 컴포넌트를 두 곳에 놓고 각각 다른 색을 칠할 수 있습니다.

지금까지 IRIS 는 그 면들을 **기본 회색**으로 렌더하고 있었습니다.

| | 상속 대상 버킷 | 잘못 나오던 서브인스턴스 |
|---|---|---|
| 골프존 (실내) | 54 / 555 (9.9%) | **109곳** |
| 세종 (실외) | 188 / 469 (40.1%) | **108곳** |

---

## 2. 어떻게

### 2.1 glTF 로는 안 되는 이유

메시가 인스턴스 간 공유되므로 재질을 메시에 박아야 하고, 인스턴스별로 다르게
하려면 **메시를 복제**해야 합니다 → 인스턴싱 이득이 사라집니다.

### 2.2 레이트레이서는 됩니다 — 그리고 RTXPT 에 이미 있었습니다

RTXPT 는 재질 인덱스를 **서브인스턴스(인스턴스 × 지오메트리) 단위**로
들고 있습니다.

```cpp
// Rtxpt/Shaders/SubInstanceData.h
uint GlobalGeometryIndex_PTMaterialDataIndex;
//   상위 16비트 = 지오메트리 인덱스, 하위 16비트 = 재질 인덱스
```

**지오메트리는 한 벌만 두고 인스턴스마다 다른 재질을 낼 수 있습니다.**
[05번 5절](05-씬-델타-프로토콜.md)이 설계한 그대로이고, 데이터 구조가 이미
있었으므로 채우기만 하면 됐습니다.

### 2.3 구현

| 곳 | 하는 일 |
|---|---|
| `SceneBuilder::BuildMesh` | 재질 없는 버킷 자리를 기록 (`m_inherits`) |
| `SceneBuilder::ApplyInheritedMaterial` | 인스턴스 재질을 그 자리에만 꽂아 콜백으로 넘김 |
| `IrisScene` | 콜백에서 `MeshInstanceEx` 로 내려 저장 |
| `MeshInstanceExtension::IrisPerGeometryMaterial` | 인스턴스별 덮어쓰기 |
| `MaterialsBaker::Update` | 덮어쓰기가 있으면 그것을 우선 |

`SceneBuilder` 는 **RTXPT 타입을 모릅니다.** 적용은 콜백으로 넘깁니다.

## 3. 여기서 죽은 지점

**덮어쓰기 전용 머티리얼은 씬 그래프의 머티리얼 목록에 없습니다.**

`SceneGraph::RegisterLeaf` 는 **지오메트리를 통해서만** 머티리얼을 등록합니다.
어떤 머티리얼이 인스턴스 덮어쓰기에만 쓰이면 그 목록에 없고, 그러면
`MaterialsBaker` 가 `PTMaterial` 을 만들지 않아 히트 시 **널 참조로 죽습니다.**
실제로 0xC0000005 로 죽었습니다.

→ `CreateRenderPassesAndLoadMaterials` 가 인스턴스 덮어쓰기 머티리얼도 함께
등록하도록 했습니다. 등록이 빠진 경우를 대비해 원래 재질로 되돌리는 방어도
넣었습니다 — 색이 틀리는 편이 죽는 것보다 낫습니다.

---

## 4. 정직하게 — 설계의 핵심 이점은 아직 실증되지 않았습니다

이 설계의 홍보 문구는 *"같은 지오메트리를 인스턴스마다 다른 색으로"* 입니다.
**두 실제 모델에서 그 경우가 한 건도 없었습니다.**

| | 상속 대상 정의 중 인스턴스 재질이 지정된 것 | 그중 **서로 다른 재질로 2회 이상** 배치된 것 |
|---|---|---|
| 골프존 | 28 | **0** |
| 세종 | 94 | **0** |

즉 이 두 모델에서는 **"정의당 재질 하나"** 로도 충분했고, 메시를 복제하는
단순한 방법으로도 같은 결과가 나왔을 것입니다.

**그래도 이 구현이 옳습니다.**

- 217곳의 서브인스턴스가 **기본 회색으로 잘못 나오던 것**이 고쳐집니다.
  이것만으로도 필요한 작업이었습니다
- 추가 비용이 사실상 없습니다. 데이터 구조가 이미 있었고, 지오메트리를
  복제하지 않으므로 BLAS 도 늘지 않습니다
- 같은 컴포넌트를 다른 색으로 칠하는 것은 **SketchUp 의 평범한 사용법**입니다.
  두 모델에 없었을 뿐 언제든 나옵니다. 그때 메시 복제 방식이었다면
  인스턴싱이 무너집니다

> 기록해 두는 이유: 나중에 "재질 상속이 인스턴싱을 지켰다"고 말할 때
> **이 두 모델은 그 근거가 아닙니다.** 근거는 아직 없습니다.

## 6. 남은 것

| | |
|---|---|
| 알파 테스트·투과 재질 덮어쓰기 | BLAS 지오메트리 플래그는 **메시 단위**라 인스턴스별로 못 바꿉니다. 불투명 재질에는 문제없고, 반투명을 인스턴스별로 덮어쓰면 그때 봐야 합니다 |
| 발광 재질 덮어쓰기 | `LightsBaker` 는 `geometry->material` 을 봅니다. 덮어쓰기로 발광을 넣으면 광원으로 잡히지 않습니다 |
| 중첩 상속 | SketchUp 은 여러 단계 위까지 올라가며 상속합니다. 현재는 **직계 인스턴스 한 단계**만 봅니다 |
