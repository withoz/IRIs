# 재질 상속 (Phase 1 · 3단계)

> 작성일: 2026-09-08
> 설계 근거: [05번 5절](05-씬-델타-프로토콜.md) — "glTF가 못 하는 것"

## 1. 무엇을 고쳤나

SketchUp 에서 면에 재질이 없으면 **상위 인스턴스의 재질**을 씁니다.
같은 컴포넌트를 두 곳에 놓고 각각 다른 색을 칠할 수 있습니다.

지금까지 IRIS 는 그 면들을 **기본 회색**으로 렌더하고 있었습니다.

| | 상속 대상 버킷 | 잘못 나오던 서브인스턴스 |
|---|---|---|
| 골프존 (실내) | 54 / 555 (9.9%) | **109곳** |
| 세종 (실외) | 188 / 469 (40.1%) | **108곳** |

---

## 2. 어떻게

### 2.1 glTF 로는 안 되는 이유

메시가 인스턴스 간 공유되므로 재질을 메시에 박아야 하고, 인스턴스별로 다르게
하려면 **메시를 복제**해야 합니다 → 인스턴싱 이득이 사라집니다.

### 2.2 레이트레이서는 됩니다 — 그리고 RTXPT 에 이미 있었습니다

RTXPT 는 재질 인덱스를 **서브인스턴스(인스턴스 × 지오메트리) 단위**로
들고 있습니다.

```cpp
// Rtxpt/Shaders/SubInstanceData.h
uint GlobalGeometryIndex_PTMaterialDataIndex;
//   상위 16비트 = 지오메트리 인덱스, 하위 16비트 = 재질 인덱스
```

**지오메트리는 한 벌만 두고 인스턴스마다 다른 재질을 낼 수 있습니다.**
[05번 5절](05-씬-델타-프로토콜.md)이 설계한 그대로이고, 데이터 구조가 이미
있었으므로 채우기만 하면 됐습니다.

### 2.3 구현

| 곳 | 하는 일 |
|---|---|
| `SceneBuilder::BuildMesh` | 재질 없는 버킷 자리를 기록 (`m_inherits`) |
| `SceneBuilder::ApplyInheritedMaterial` | 인스턴스 재질을 그 자리에만 꽂아 콜백으로 넘김 |
| `IrisScene` | 콜백에서 `MeshInstanceEx` 로 내려 저장 |
| `MeshInstanceExtension::IrisPerGeometryMaterial` | 인스턴스별 덮어쓰기 |
| `MaterialsBaker::Update` | 덮어쓰기가 있으면 그것을 우선 |

`SceneBuilder` 는 **RTXPT 타입을 모릅니다.** 적용은 콜백으로 넘깁니다.

---

## 3. 여기서 죽은 지점

**덮어쓰기 전용 머티리얼은 씬 그래프의 머티리얼 목록에 없습니다.**

`SceneGraph::RegisterLeaf` 는 **지오메트리를 통해서만** 머티리얼을 등록합니다.
어떤 머티리얼이 인스턴스 덮어쓰기에만 쓰이면 그 목록에 없고, 그러면
`MaterialsBaker` 가 `PTMaterial` 을 만들지 않아 히트 시 **널 참조로 죽습니다.**
실제로 0xC0000005 로 죽었습니다.

→ `CreateRenderPassesAndLoadMaterials` 가 인스턴스 덮어쓰기 머티리얼도 함께
등록하도록 했습니다. 등록이 빠진 경우를 대비해 원래 재질로 되돌리는 방어도
넣었습니다 — 색이 틀리는 편이 죽는 것보다 낫습니다.

---

## 4. 정직하게 — 설계의 핵심 이점은 아직 실증되지 않았습니다

이 설계의 홍보 문구는 *"같은 지오메트리를 인스턴스마다 다른 색으로"* 입니다.
**두 실제 모델에서 그 경우가 한 건도 없었습니다.**

| | 상속 대상 정의 중 인스턴스 재질이 지정된 것 | 그중 **서로 다른 재질로 2회 이상** 배치된 것 |
|---|---|---|
| 골프존 | 28 | **0** |
| 세종 | 94 | **0** |

즉 이 두 모델에서는 **"정의당 재질 하나"** 로도 충분했고, 메시를 복제하는
단순한 방법으로도 같은 결과가 나왔을 것입니다.

**그래도 이 구현이 옳습니다.**

- 217곳의 서브인스턴스가 **기본 회색으로 잘못 나오던 것**이 고쳐집니다.
  이것만으로도 필요한 작업이었습니다
- 추가 비용이 사실상 없습니다. 데이터 구조가 이미 있었고, 지오메트리를
  복제하지 않으므로 BLAS 도 늘지 않습니다
- 같은 컴포넌트를 다른 색으로 칠하는 것은 **SketchUp 의 평범한 사용법**입니다.
  두 모델에 없었을 뿐 언제든 나옵니다. 그때 메시 복제 방식이었다면
  인스턴싱이 무너집니다

> 기록해 두는 이유: 나중에 "재질 상속이 인스턴싱을 지켰다"고 말할 때
> **이 두 모델은 그 근거가 아닙니다.** 근거는 아직 없습니다.

## 7. 재질 매핑 (2026-09-08 추가)

상속과 별개로, **SketchUp 재질을 어떻게 PBR 로 옮기는가**가 남아 있었습니다.
"재질이 맞지 않는다"는 보고를 받고 세 가지를 고쳤습니다.

### 7.1 색 공간 — sRGB 를 선형으로

프로브가 `c.red / 255.0` 을 보내고 있었습니다. SketchUp 의 `Color` 는
**화면 표시용 sRGB** 이고, [05번 명세 4.3절](05-씬-델타-프로토콜.md)도 렌더러도
**선형**을 기대합니다.

> sRGB 0.5 는 선형 **0.21** 입니다. 변환하지 않으면 모든 색이 밝게 뜹니다.

프로브에서 변환합니다 — 명세가 선형이라고 말하고 있으므로 그쪽이 맞습니다.

### 7.2 텍스처 이중 착색

프로브가 내보내는 PNG 는 `image_rep(true)` 로 뽑은 것이라 **이미 재질 색이
입혀져 있습니다**. 그런데 렌더러가 `baseOrDiffuseColor` 를 또 곱하고 있었습니다.

더 나쁜 것은, **SketchUp 의 `Material#color` 는 텍스처 재질일 때 텍스처의
평균색을 돌려준다**는 점입니다. 그것을 곱하면 표면 전체가 그 평균색으로
어두워집니다.

→ **텍스처가 있으면 기본색은 흰색**으로 둡니다.

### 7.3 반투명 재질을 유리로

| | |
|---|---|
| 이전 | `alpha < 1` → `AlphaBlended` |
| 지금 | `alpha < 1` **且 텍스처 없음** → `Transmissive`, `transmissionFactor = 1 - alpha`, `roughness 0.05` |

건축 모델에서 알파가 걸린 단색 재질은 거의 항상 유리입니다 — 이 모델에도
`Translucent Glass`, `black glass` 등 **6개**가 있습니다. `AlphaBlended` 로 두면
굴절도 반사도 없는 '유령'처럼 보입니다. **패스트레이서가 유리를 제대로 그릴 수
있는데 그러지 않을 이유가 없습니다.**

텍스처가 있는 반투명은 잎사귀 컷아웃일 수 있어 그대로 둡니다.

### 7.5 텍스처 v 뒤집기 — 그리고 진단 방법 (2026-09-08)

로고 글자가 **좌우로 뒤집히고 한 면에 두 번** 나왔습니다.

원인은 하나였습니다. SketchUp 의 텍스처 좌표는 v 가 **위로** 증가하고 이미지의
아래쪽 행이 v=0 입니다. 렌더러(glTF·D3D 관례)는 이미지의 **첫 행**이 v=0 입니다.
`v -> 1 - v` 하나로 두 증상이 모두 사라졌습니다.

#### 어떻게 찾았나 — 이 방법이 본체입니다

세 번 틀린 가설을 세운 뒤에야 방법을 바꿨습니다.

| 가설 | 결과 |
|---|---|
| 뒷면 재질 면의 UV | 그런 면이 7,460개 있었지만 원인 아님 |
| UVQ 의 q 부호 | 실측 q 는 전 정점에서 **1.0** |
| 거울 배치(행렬식 음수) | 변환 왕복은 부호를 정확히 보존(2000개 검증) |

그다음 **렌더러를 의심하기 전에, 우리가 내보낸 것만으로 화면을 재현**했습니다.

```
.irisb 의 UV·인스턴스 변환·카메라  +  내보낸 PNG
        -> 깊이 버퍼를 넣어 오프라인 래스터라이즈
        -> 렌더 화면과 동일 (로고 두 개, 둘 다 거울상)
```

이것으로 **렌더러는 무죄**임이 확정됐고, 남은 탐색 범위가 SketchUp 추출 한
곳으로 줄었습니다. 그 뒤 (u,v)·(-u,v)·(u,-v)·(-u,-v) 네 조합을 그려 보고
답을 골랐습니다.

> 이 확인이 없었다면 렌더러의 샘플러·좌표계·BLAS 를 뒤지고 있었을 것입니다.
> **파이프라인 문제는 각 단계의 출력을 그 단계의 언어로 재현해 보면 갈립니다.**

#### 한 가지 남은 미검증

같은 작업에서 "재질을 뒷면에서 가져왔으면 UV·법선·감김도 뒷면 것으로" 를
함께 넣었습니다(7,460면). **원리는 옳지만**(앞면 재질 면의 뒷면 UV 는 실측상
쓰레기 값입니다 — u 0~29250 같은) 이번 증상의 원인은 아니었고, 독립적으로
검증하지 않았습니다.

### 7.4 아직 손대지 않은 것 — 거칠기와 금속성

**SketchUp 은 PBR 파라미터를 주지 않습니다.** 지금은 전부
`roughness 0.5 / metalness 0` 고정이고 유리만 0.05 입니다.

| 접근 | 비고 |
|---|---|
| 이름 규칙 (`*metal*`, `*mirror*`, `*matte*`) | 값싸지만 사용자 명명에 의존 |
| IRIS 자체 재질 UI | 정공법. 사용자가 조정하고 IRIS 가 기억한다 |
| Enscape 재질 속성 읽기 | [09번 문서](09-조명-설계.md)의 조명 프록시와 같은 발상. 속성 사전에 값이 있으면 그대로 |

**미결정 B(PBR 파라미터 범위)** 가 이것이며, 조명 시스템(4단계)과 함께 정합니다.
